## 1. 已批准交互

| HERMES 手势 | 行为 | 手表标签 |
| --- | --- | --- |
| 左 | 回到 Codex，保留三应用循环 | CYCLE |
| 上 | 按侧栏顺序打开上一个会话，可跨项目 | PREV |
| 下 | 按侧栏顺序打开下一个会话，可跨项目 | NEXT |
| 右 | 跳到下一个 Project，恢复其上次打开的会话 | PROJECT |

每次接受的手势直接打开目标，不引入选择确认或项目/会话二级模式。
示例：项目 A 的 A1、A2，项目 B 的 B1、B2，连续下滑为 A1→A2→B1→B2；
上滑反向。项目标题不占用上下导航的一步。上下到全列表首尾后停止；
右滑按项目顺序循环。空项目由上下跳过，但右滑可进入且不自动创建会话。
新建会话保留在 Hermes 原界面，不再由手表右滑触发。

SUPER 的项目上下切换、右滑 Tab 和 Codex 原行为完全不变。

## 3. 已认可的职责划分与技术门槛

1. 手表继续只发送方向，显示固定标签；不接收项目名或会话名。
2. Companion 校验前台 PID 和 `com.nousresearch.hermes`，发送三个专用的
   固定导航快捷键；不保存项目树、不获取应用内容、不发全局事件。
3. Hermes 侧导航适配层以自身侧栏模型为唯一顺序来源，执行前一个会话、
   后一个会话、后一个项目。它复用 Hermes 的打开/聚焦/展开/滚动行为，
   不复制会话切换器、不通过 DOM、Accessibility 或数据库抓取重建侧栏。

优先验证官方插件入口。插件若无法通过公开接口获得正确侧栏视图和安全
项目入口，则停止插件实现；另行提交 Hermes 最小核心命令/SDK 扩展方案供
批准，不导入私有模块、不补丁已安装的应用、不自行重建或重新签名 Hermes。
不使用会话列表 RPC 另建一个与侧栏顺序可能不一致的替代列表。

候选专用按键为 Control-Option-Up / Down / Right，仅在 Hermes 前台路由；
它们不是已存在的 Hermes 内建功能。最终绑定要经过版本与冲突验证。
旧 Control-Tab 行为和应用内新建快捷键不覆盖。

## 4. 详细导航规则

- 范围为当前窗口、当前连接与 Profile 下的项目侧栏；Project 不等于 Profile。
  不跨连接、不切换 Profile、不进入 Bots 或归档/隐藏会话。
- 使用侧栏项目与会话的规范顺序，包含可展开项目下的会话；折叠只影响展示，
  不把该项目排除。目标命中后展开其祖先并滚动到可见位置。
- 顺序不能因为本次打开动作而重排。若当前排序机制会因访问变动，Hermes
  导航层从首个导航手势建立顺序快照，后续手势沿用；窗口失焦、用户以鼠标或
  原生导航手动选择、结构变化或手动重排时结束该快照。下次手势重新取序并按
  当前稳定标识定位，不能靠名称或列表下标长期追踪。
- 虚拟列表和分页不能让屏幕外会话被误判为列表末尾。技术验证必须证明
  Hermes 原生模型可提供或按需加载下一导航目标；没有这一能力即不通过门槛，
  不由 Companion 扫描数据来补齐。
- 右滑恢复目标项目最近一次成功打开的会话；无有效记录时进入第一条可导航
  会话，空项目进入项目视图。失效记录不创建替代会话。
- 最近会话记录限于 Hermes 内存中的导航标识；不传给 Companion、不新建
  持久化文件，重启无记录时使用上述确定回退。
- 当前没有已选会话：处于有会话的项目时下滑进入第一条、上滑进入最后一条；
  空项目上下分别寻找后一个/前一个有会话项目；无项目上下进入列表首/尾，
  右滑进入第一个项目。整个范围为空时无操作，不自动新建。
- 无项目归属的会话暂不纳入此项目导航；手动打开它们时按无项目入口处理。
- 草稿和运行中的任务交给 Hermes 既有切换机制保护；导航不发送消息、不停止
  任务、不关闭 Tab、不丢弃草稿。没有安全切换路径时拒绝操作。
- 设置页、模态对话框、输入法组合态及不具备项目侧栏的独立会话窗口不执行
  此导航。普通聊天输入框允许专用修饰键，不抢占裸方向键或文本输入。
- 保留现有 800ms 释放门控；本轮“流畅”指顺序和直接打开，不宣称支持更快
  连滑。导航切换处理中不积压手势；失败不自动重试，不乐观更新当前位置。
- 一次手势至多一次激活；离开窗口或停用适配层后，迟到回调不得重新导航。

## 5. 隐私和授权边界

用户已批准 Hermes 内部使用必要导航元数据：不透明项目/会话标识、归属、
侧栏顺序、当前选择及内存中的最近会话记录。这是相对旧方案“只发按键”新增
的职责，尚未实施；不得把该批准扩展为替换或修改正在使用的 Hermes。

适配层不读取消息正文、提示词、文件内容、凭据，不订阅消息流，不将名称、
路径、标识、数量或内容发给手表/Companion/外部服务。正常打开会话时 Hermes
自身加载聊天内容属于原应用行为，不供适配层读取、分析或记录。
导航适配不使用 shell、AppleScript、私有 Space API、剪贴板或任意宏。
保留安装身份、LaunchAgent、设备绑定与日志配置。无推送、合并或上游 PR 授权。

## 6. 验证与分阶段门槛

1. 审阅本设计，明确批准有限导航元数据边界和技术验证范围。
2. 核对已安装 Hermes 版本及其公开能力，不读取用户配置；使用独立的合成数据
   环境证明插件/官方命令路径。若不能满足，提供最小 Hermes 扩展差异再审阅。
3. 先验证物理键盘三条专用命令，再接手表；不能将事件投递成功作为执行成功。
4. 测试项目跨越、空项目、折叠、首尾、右滑循环、最近会话失效、重排/删除、
   无项目入口、窗口/连接隔离、草稿保留、快速输入、失败与过期回调。
5. Companion 覆盖固定映射、前台/权限门控，固件测试标签边界和原输入隔离；
   重跑相关 native、Swift harness/release，并分开报告 XCTest 环境限制。
6. 展示 HERMES 的 PROJECT 标签预览；用户批准安装范围后再备份和安装。
   固件刷写仍需新枚举端口和当次精确确认。
7. 实机分别验证 HERMES 顺序导航、SUPER/Codex 无回归、随机颜色、麦克风与
   额度。所有未观察的结果为未验证。

未修改任何实现文件、安装文件或固件。本设计不替代既有中心 UI 的待刷写验收。
